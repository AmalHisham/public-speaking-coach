Version: 1.0

---

# **Purpose**

This document is the single source of truth for engineering decisions, coding standards, repository rules, and AI-assisted development.

All contributors and AI coding agents must follow this document.

If implementation conflicts with this guide, this guide takes precedence.

---

# **Product Philosophy**

Public Speaking Coach is an analytics platform.

It is not an AI judge.

The system helps users improve communication skills through objective measurement and actionable coaching.

---

# **Core Architecture Philosophy**

MediaPipe provides signals.

Metrics Engine produces facts.

OpenAI provides interpretation.

Responsibilities must remain separate.

---

# **Engineering Principles**

## **Principle 1**

Measure only what can be objectively calculated.

---

## **Principle 2**

Every metric must be explainable.

---

## **Principle 3**

Metrics are generated by formulas.

Never by AI.

---

## **Principle 4**

Prefer simplicity over cleverness.

---

## **Principle 5**

Code is written for humans first.

# **Metrics Philosophy**

Metrics are the product.

Protect them.

---

# **Allowed Metrics**

Speech Metrics:

* Speaking Pace  
* Filler Usage  
* Pause Quality

Vision Metrics:

* Camera Engagement  
* Posture Stability

---

# **Forbidden Metrics**

Never create:

* Confidence Score  
* Charisma Score  
* Leadership Score  
* Executive Presence Score  
* Persuasiveness Score  
* Trustworthiness Score  
* Audience Engagement Score  
* Passion Score  
* Authenticity Score

Reason:

Cannot be measured objectively.

---

# **AI Rules**

AI may:

* Explain metrics  
* Generate reports  
* Generate recommendations

AI may NOT:

* Calculate metrics  
* Modify metrics  
* Override metrics

---

# **Browser-First Rule**

Audio and video processing occur in browser.

Allowed:

* MediaPipe processing  
* Speech recognition  
* Metric calculation

Forbidden:

* Continuous video streaming to backend

Reason:

Lower infrastructure cost.

Better scalability.

---

---

# **Metric Standards**

Every metric requires:

* Metric ID  
* Version  
* Inputs  
* Formula  
* Output  
* Confidence  
* Limitations

---

Every metric requires tests.

Known input.

Known output.

---

# **Metric Versioning**

Required.

Examples:

Speaking Pace v1

Speaking Pace v2

Historical sessions must preserve versions.

---

# **Error Handling**

Never swallow errors.

Forbidden:

catch {}

---

Required:

catch(error) {

  logger.error(error)

}

---

# **Graceful Failure Rules**

System must handle:

* Camera unavailable  
* Microphone unavailable  
* Face not detected  
* Pose not detected  
* OpenAI failure  
* Database failure

Application must remain functional.

---

# **Security Rules**

Never expose:

* OpenAI API Keys  
* Database Credentials  
* Clerk Secrets

---

All server inputs must be validated.

---

Users can access only their own data.

Ownership checks are mandatory.

---

# **Logging Rules**

Log:

* Session starts  
* Session completions  
* Metric failures  
* OpenAI failures

Do not log:

* Secrets  
* Passwords  
* Tokens

---

# **Testing Standards**

Required:

* Unit Tests  
* Integration Tests

---

Metric calculators require:

Known input.

Known expected output.
